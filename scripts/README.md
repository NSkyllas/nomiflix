# scripts/

Pipeline implementation goes here. Expected pieces (see `docs/SPEC.md` §3 for full logic):

- `probe.py` — done. Wraps `ffprobe`, returns codec/resolution info + branch decision (`scale`/`codec_only`/`skip`)
- `transcode.py` — done. Wraps `ffmpeg` for the `scale`/`codec_only` branches; copies (not re-encodes) whichever of video/audio is already compliant, since CPU is the tight resource
- `parse_credits.py` — done. Parses a raw IMDB "Full Cast & Crew" paste into `{director, writer, cast, crew}`, see SPEC §6.1. Fail-loud (`CreditsParseError`) on anything unrecognized. Tested against a full real IMDB paste (Solaris, 1972, ~150 lines) — found and fixed two real IMDB formatting quirks along the way: a photo-less cast member's caption line is their bare name repeated (no " in Title (Year)" to distinguish it from a real Name line — detected via exact-duplicate-of-previous-line instead), and a lone department member with nothing extra to say has no detail line at all (next line is directly the next department header, not their role). Known unresolvable gap: two consecutive department members with *neither* having role text can't be told apart from one Name+detail pair — no syntactic signal survives IMDB's HTML being flattened to plain text.
- `write_nfo.py` — done. Builds a local Kodi/Jellyfin NFO (`<movie>` or `<episodedetails>`) from the upload sidecar's Title/Year/Genre/Season+Episode, plus `<director>`/`<credits>`(writer)/`<actor>` from parsed credits if present — those three are the only person-categories Kodi/Jellyfin's NFO schema has slots for, so Producer/Composer/etc. never reach Jellyfin regardless of parsing quality. No plot/overview field. Known gap: the upload form has one Title field, which doubles as show name AND per-episode title for shows — no separate episode-title field yet
- `move_into_library.py` — done. Applies Jellyfin naming convention, moves into `Movies/` or `Shows/`. Refuses to overwrite an existing destination (raises rather than silently clobbering)
- `process_item.py` — done. Orchestrates one `_Processing/<base>.*` pair: parse credits (if any, before anything else — fail fast rather than burning a transcode first) → probe → transcode (if needed) → move into library → place poster → write parsed credits as `<video basename>-credits.json` (raw `.txt` deleted once parsed) → write NFO, or route to `_Failed/` on any expected error (including a credits parse failure). Verified end-to-end against synthetic files (transcode branch, skip branch, corrupt-input failure) and against the real Solaris credits paste all the way through to the final NFO/JSON
- `watcher.sh` — done. inotifywait dispatcher, mirrors Nomify's `inbox-watcher.sh` (per-base `flock`, catch-up scan of pairs already waiting at startup) plus the `_Inbox/` → `_Processing/` move Nomiflix's design calls for. Also moves the optional poster and credits files. Verified live: background-started, pairs dropped into `_Inbox/` while running get picked up automatically (both upload orderings), plus a catch-up run against a pair dropped while no watcher was running
- `../upload/app.py` + `../upload/templates/index.html` — done. Flask upload form mirroring Nomify's (video + Title/Year/Type/Season+Episode/Genre/poster/credits, all server-side validated), writes the random-base-name video+JSON(+poster)(+credits) set into `_Inbox/`. Verified live end-to-end: real `curl` upload with a poster and a real IMDB credits paste (Solaris 1972) → `_Inbox/` → `watcher.sh` → landed correctly in `Movies/` with matching video/NFO/poster/credits-JSON basenames; all validation error paths (missing title, bad year, show without season/episode, unsupported video extension, no file, missing genre) confirmed to reject cleanly with no partial files left in `_Inbox/`. Has a JS-driven upload progress bar (`XMLHttpRequest` + `upload.onprogress`, since a plain form POST gives the browser no progress hook) — server-side logic unchanged, response HTML just gets swapped into the page on completion. Verified the page still renders correctly with it; the actual in-browser progress animation needs a live check (no browser automation available here).
- `handbrake_extract.py` (later) — DVD `VIDEO_TS`/ISO extraction step, see SPEC §5

The full pipeline (upload → watch → parse credits → probe → transcode → file → NFO/poster/credits-JSON) is now built and verified locally end-to-end. Remaining: real-world testing against actual movie files (not synthetic `ffmpeg testsrc` clips), and eventual VPS deployment (systemd units, Jellyfin config — see `deploy/`).

Keep the queue/lock mechanism simple (single lock file is enough per SPEC §3.3) — no need for a job queue framework at this scale.

Local dev note: this repo has no venv/requirements.txt, matching Nomify's convention of using the system's `python3-flask` package rather than pip. `python3-flask` was installed via `sudo apt install python3-flask` for local testing.
